# Запуск и проверка вьювера

Рабочая модель — Python/build123d в `cadpy/`. Просмотр через OCP CAD Viewer;
FreeCAD для запуска не нужен. Хаб `androsaur-hub` тоже не требуется.

## Запуск

Из корня репозитория:

```bash
./cadpy/viewer.sh
```

Открыть **http://127.0.0.1:3939/viewer**. Можно открыть вкладку после запуска,
обновить страницу (F5) или открыть ещё одну вкладку: последняя модель хранится
в памяти сервера и отправляется вкладке сразу, как только она зарегистрировалась.
Логотип OCP при загрузке страницы скрыт: окно появляется, когда пришла модель
(если модели нет, через 15 с покажется логотип). Первое построение после запуска
занимает некоторое время, пока оно не закончилось, окно пустое.
Процесс нужно оставить работающим. Остановка в терминале — Ctrl+C.

## Остановка и перезапуск

Если вьювер запущен в фоне, останавливать по номерам процессов, а не `pkill -f viewer.sh`
(такой шаблон совпадёт и с текущей командой оболочки и завершит её):

```bash
ps -eo pid,args | grep -E "viewer_server.py --port 3939|ocp123d -o 3939" | grep -v grep
kill <pid> <pid>      # viewer_server.py и ocp123d (и процесс viewer.sh, если есть)
ss -ltnp | grep 3939   # убедиться, что порт свободен
./cadpy/viewer.sh      # запустить заново
```

Править `viewer_server.py` можно, только перезапустив вьювер: он не перечитывается сам.
Изменения `view.py` и модели `ocp123d` подхватывает сам.

Для другого порта: `./cadpy/viewer.sh 3940` (такой же порт указать в URL и проверках).
При занятом порте сначала выяснить, какой процесс его использует; не завершать
чужие процессы. Повторный запуск на занятом порте должен закончиться ошибкой.

При первой установке:

```bash
cd cadpy
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
./viewer.sh
```

`viewer.sh` ждёт готовности сервера, затем запускает `ocp123d`, который строит
модель и следит за изменениями. `TILT` и `PAN` заданы в `view.py`.
При необходимости вручную переслать модель:

```bash
cd cadpy
.venv/bin/python view.py
```

## Проверка отображения

Агент отображение в браузере не проверяет (решение владельца 2026-11-11): после запуска
`./cadpy/viewer.sh` он сообщает адрес `http://127.0.0.1:3939/viewer` и честно говорит,
что отображение не проверено. Вкладку проверяет владелец. Для диагностики остаются
`curl -fsS http://127.0.0.1:3939/health` и `cadpy/viewer_status.py`.

## Если вкладка пустая или виден логотип

Посмотреть `curl -fsS http://127.0.0.1:3939/health` и журнал запуска:

- `model_cached: false` — модель ещё строится либо `view.py` завершился ошибкой.
  Дождаться построения или устранить ошибку из журнала.
- `browser_count: 0` — страница не зарегистрировалась; проверить URL, соединение
  WebSocket и ошибки JavaScript/WebGL в консоли браузера (F12).
- Модель сохранена, браузер подключён, но `ready: false` — вкладка ещё не
  подтвердила дерево сборки. Проверить журнал и консоль браузера.
- `/health` возвращает 404 — запущен прежний сервер напрямую через
  `python -m ocp_viewer`. Использовать проектный `viewer.sh`.

История:

- 2026-11-09: прежний сервер отправлял модель только текущему клиенту и не сохранял её
  для позднего открытия/обновления вкладки. Теперь `viewer_server.py` сохраняет модель.
- 2026-11-11: модель отправлялась только после статуса со страницы, а при заставке он не
  приходил, поэтому вкладка оставалась с логотипом. Теперь вкладка регистрируется по первому
  сообщению (`L`), и модель уходит сразу; статус остаётся только для подтверждения
  (`ready`). Логотип скрыт стилем в выдаваемой странице (`hide_splash`), чтобы он не
  мелькал при F5. Файлы библиотеки в `.venv` не менялись.

Регрессионная проверка доставки без построения CAD: из `cadpy/`
`.venv/bin/python -m unittest test_viewer_server -v`.
