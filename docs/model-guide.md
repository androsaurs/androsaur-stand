# Работа с моделью

Модель — обычный Python-код на [build123d](https://github.com/gumyr/build123d) 0.13 (BRep). Править константы и функции, смотреть результат
в просмотрщике, проверять скриптами. Отдельные файлы CAD вручную не редактируются.

## Установка

```bash
cd cadpy
python3 -m venv .venv                       # Python 3.12
.venv/bin/pip install -r requirements.txt   # build123d, ocp_vscode, ocp_viewer, matplotlib, numpy
```

## Просмотр

`./viewer.sh` запускает просмотрщик OCP CAD Viewer на порту 3939 и следит за `view.py`: сохранили файл, модель перерисовалась.
Адрес — `http://127.0.0.1:3939/viewer`. Сервер хранит последнюю модель и автоматически передаёт её новой или обновлённой вкладке
после готовности страницы. Проверка фактической загрузки: `.venv/bin/python viewer_status.py` (`ready: true`), затем скриншот
через `--screenshot` и его визуальный просмотр. Полная инструкция и диагностика — [viewer.md](viewer.md).
В `view.py` меняются `TILT` (0 — площадка горизонтально, 90 — вертикально) и `PAN`.

В дереве просмотрщика группы **stand** (механизм), **holder** (держатель, телефон, штекер), **enclosure** (корпус, полка, ножки), **electronics**
(динамик, платы, блок питания, втулки) и **fasteners** (крепёж, красный, по узлам: stand-to-lid, box-halves, box-feet, shelf-legs, amplifier,
speaker, power-module, servo-pan, servo-tilt, side-plates, holder). Любую группу можно выключить. Цвета, прозрачность (только оболочки: корпус,
телефон, полка; остальное непрозрачное) и состав групп задаются в одном месте, `palette.py`; дерево собирает `scene.py` для просмотра и экспорта.

## Скрипты

| Скрипт | Что делает |
| --- | --- |
| `check.py <углы наклона>` | Пересечения всех пар деталей при заданных наклонах, например `check.py -2 45 90 100` |
| `pancheck.py` | Наклон 0/45/90 × поворот 45/90/135/180 |
| `export.py [наклон] [поворот] [--glass] [--hw] [--out файл]` | STEP с теми же группами, именами и цветами → `exports/androsaur-stand-assembly.step` (открывается во FreeCAD); `--hw` добавляет крепёж, `--glass` оставляет прозрачность оболочек |
| `shots.py` | Картинки для документации → `docs/img/` |
| `leg_view.py`, `render.py` | Старые вспомогательные картинки (матплотлиб), результат в `cadpy/out/` |

`assemble(tilt_deg, pan_deg, cable, box, speaker)` в `pantilt.py` возвращает словарь «имя детали → тело». Параметры `box=False`
отключает корпус, `speaker=False` — всё содержимое корпуса. Имена деталей — в [part-names.md](part-names.md).

## Как проверять изменения

1. Изменить константу в `pantilt.py`, `clip_holder.py`, `enclosure.py` и т. д.
2. Посмотреть в просмотрщике.
3. `check.py -2 45 90 100` — пересечений быть не должно. Зазоры и расстояния считать через `a.distance_to(b)` и
   объём пересечения `a.intersect(b)` (результат может быть `None`, `ShapeList` или телом — учитывать все случаи).
4. Для изменений полки и корпуса проверять, что нужные детали остаются цельными: `len(shape.solids()) == 1`.

## Правила работы

- Не запускать тяжёлые проверки без ограничения памяти (`ulimit -v`): облака из сотен тысяч точек и сетки через trimesh
  уже один раз съели всю память. Использовать точные операции BRep.
- Верх полки должен оставаться плоским, она печатается плитой вниз (см. [enclosure.md](enclosure.md)).
- Всё, что висит под полкой или на ней, проверять по пересечениям с динамиком, ESP32 (штыри снизу) и стенками.
- Не менять конструкцию, оси и положения соседних деталей без прямого указания владельца (правило проекта, см. AGENTS.md).

## Что делает каждая часть кода

- `pantilt.py` — параметры, функции деталей (`servo`, `base`, `carrier`, `plate_horn_side`, `plate_shaft_side`, `platform`), `assemble`.
- `clip_holder.py` — `body`, `grip`, `phone`, `plug`, `cable` (держатель из двух деталей и габарит телефона).
- `enclosure.py` — `lower`, `upper`, `shelf`, `foot` и положения всего внутри корпуса.
- `speaker.py`, `esp32.py`, `amp.py` — габариты покупных деталей.
